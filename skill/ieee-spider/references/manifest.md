# Fixed Manifest Protocol

Manifests are generated by the crawler. Agents may read and select records,
but must not edit them manually.

The schemas below are the current generated contract. If a valid IEEE workflow
requires an additional field or changed representation, update the generator
and this reference together rather than patching individual output files.

## Search Manifest

Search outputs:

```text
data\jobs\<job-name>\manifest.jsonl
data\jobs\<job-name>\manifest.csv
data\jobs\<job-name>\manifest.md
```

Each JSONL record has these fields in fixed order:

```text
manifest_version
record_id
status
title
authors
year
doi
venue
publisher
publication_type
abstract
landing_page_url
oa_pdf_url
authorized_pdf_url
open_access_status
source_providers
matched_authors
matched_queries
retrieved_at
requires_authentication
download_mode
local_path
error
```

For browser-derived IEEE records, `source_providers` must contain
`ieee-xplore-browser`.

Search manifests do not require an abstract. A search-result record may have
`abstract: null`; use the serial enrichment helper to retrieve it from the
authenticated IEEE detail page.

## Record IDs

Use `record_id` for deterministic selection:

- DOI-backed record: `doi:<lowercase-doi>`
- IEEE browser record: `ieee:<article-number>`
- No DOI or article number: `sha256:<title-and-year-digest>`

Examples:

```text
doi:10.1109/twc.2020.3029143
ieee:11447568
```

## Download Manifest

Download outputs:

```text
downloads\download_manifest.jsonl
downloads\download_manifest.csv
```

Each JSONL record has these fields in fixed order:

```text
manifest_version
record_id
title
doi
mode
status
local_path
message
attempted_at
```

Status values are:

- `downloaded`
- `skipped`
- `failed`

## Abstract Enrichment Output

Abstract enrichment writes a separate JSONL file, normally named
`abstracts.jsonl` or `abstracts-<count>.jsonl`. Never replace or hand-edit the
authoritative search manifest with these records.

Each enrichment JSONL record has these fields in fixed order:

```text
manifest_version
record_id
title
year
venue
status
abstract
citation_count
patent_citation_count
full_text_views
citation_status
landing_page_url
retrieved_at
error
```

Status values:

- `ok`: a non-empty IEEE abstract was extracted.
- `failed`: the record could not be enriched after bounded retries.

Citation metric fields:

- `citation_count`: `Cites in Papers` count, when IEEE reports it.
- `patent_citation_count`: `Patent Cites` count, when IEEE reports it.
- `full_text_views`: `Full Text Views`, when IEEE reports it.
- `citation_status`: `available`, `unavailable`, or `not_reported`.

After enrichment, verify one-to-one `record_id` coverage, uniqueness, non-empty
abstracts, and unresolved failures.

Prefer using `build_paper_statistics.py` to create `statistics.json`. An
equivalent reusable generator is acceptable if the workflow cannot be handled
by the maintained script. The report includes the venue list, per-venue
citation aggregates, citation coverage, and Top Cited papers.

## Agent Reporting

After download, report:

- number of records discovered
- number downloaded
- number skipped because the file already existed
- number failed
- failed DOI or IEEE article number and error message

Do not infer success from browser state alone. Use the download manifest as the
final status source.
